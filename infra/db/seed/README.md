# 食物库种子数据（`infra/db/seed/`）

本目录存放**食物库种子** `food_items.seed.json`，由 `apps/api/prisma/seed.ts` 幂等载入数据库表 `food_items`。

> ⚠️ **数字必须可溯源**：本样例集**不虚构成千条数据**。仅收录「数值广为人知、可公开溯源」的常见中式食物，
> 用于打通数据链路与本地联调；**扩充到 ≥500 条需由客户提供有授权的数据集**（见下文）。

---

## 1. 当前样例集

| 项 | 说明 |
| --- | --- |
| 条数 | **57 条**（可覆盖主食 / 家常菜 / 外卖常见 / 奶茶 / 零食 / 水果 / 蔬菜 / 蛋白 / other 九大类） |
| 计量口径 | 每 **100g 可食部**：`kcalPer100g`（kcal）、`protein`/`fat`/`carbs`/`fiber`/`sugar`（g）、`sodium`（mg） |
| 份量单位 | `servingUnits` 提供「个/碗/杯/片/袋/块/根/只…」等自然份量 + 每单位克数（结构见 §3） |
| 落库映射 | 种子 `source: "local"`（来源标记）→ 数据库 `food_items.source = 'builtin'` |

### 数据来源性质

- 数值为**面向大众公开、被广泛引用的中国食物成分参考值**（《中国食物成分表》体系常见条目）
  与**常见连锁餐饮公开营养信息**的**四舍五入近似值**，**非官方逐条抄录**。
- 所有数值均为**估算口径**。不同烹饪方式、品牌、配比差异可达 **±20%**。

### 精度使用建议（重要）

- 本数据集**仅用于日常饮食记录与趋势参考**。
- **不得**作为医疗、营养诊断、处方或任何临床决策依据。
- 产品内相应位置需保留免责声明（对应 PRD US-04 / R1.5）。

### 当前样例集的已知缺口

- **未覆盖**微量营养素全字段（`calcium`/`iron`/`potassium`/`vitamin_d`/`b12`/`magnesium`）——留空，待二期按需补全。
- **未覆盖**条形码（`barcode`）——二期扫码功能依赖 Open Food Facts 等授权数据源。

## 2. 扩充到 ≥500 条所需的数据源与授权要求

对应架构文档 **D6** 与 PRD **Q8**。落地前需客户确认：

1. **数据来源**（择一或组合）：
   - 采购/授权《中国食物成分表》相关**标准版数据**；
   - 取得权威开放数据集（如 Open Food Facts，注意其 **ODbL** 许可与署名义务）的授权；
   - 由客户自有营养团队依据标准方法自建。
2. **授权形式**：需明确**商用授权范围**、署名要求、二次分发限制。
3. **字段完备性**：批量数据集应至少提供每 100g 的 `kcal / protein / fat / carb`，理想提供微量营养素与份量单位。
4. **可溯源要求**：每条数据建议保留来源标识（可写入 `source` 字段或新增来源列），便于审计。
5. **导入方式**：扩充数据可直接替换/追加到 `food_items.seed.json` 的 `items[]`，或新增同结构文件后由载入脚本读取。

> **红线**：禁止为了凑数而编造营养数值。宁可样例集小，也不引入不可溯源的数字。

## 3. `serving_units` 字段写法示例

`serving_units` 是 JSON 数组，元素结构（对应架构 §3.3）：

```jsonc
{
  "unit": "碗",        // 必填：份量单位（个/碗/杯/片/袋/份/支…），1–10 字
  "grams": 300,        // 必填：该单位对应克数（> 0）
  "isDefault": true,   // 可选：默认选中单位（每项至多 1 个 true）
  "label": "一中碗"    // 可选：展示别名，≤20 字
}
```

**换算规则**（引擎 / 服务端统一）：

```text
kcal = kcal_per_100g × (选定克数 ÷ 100)
选定克数 = 该单位默认克数（grams）或用户自定义克数
```

**示例**：

```json
[
  { "unit": "个", "grams": 60 },
  { "unit": "碗", "grams": 300, "isDefault": true, "label": "一中碗" },
  { "unit": "片", "grams": 20 }
]
```

`default_serving_grams` 会由载入脚本自动取「`isDefault: true`（缺省取第一个）」的 `grams`，冗余一份便于排序与快捷默认。

## 4. 载入方式

```bash
# 载入（幂等，可反复执行）
npm run db:seed -w @qsh/api
```

载入脚本以 `(name, source='builtin', created_by_user_id IS NULL)` 为业务键做 `findFirst → update/create`，
重复执行不会产生重复行。

## 7. 数据质量约束（分类 / 拼音 / 校验）

- **分类唯一口径**：`category` 只允许 9 类 —— `主食 / 家常菜 / 外卖 / 奶茶 / 零食 / 水果 / 蔬菜 / 蛋白 / other`
  （与 `apps/api/prisma/schema.prisma` 一致；旧的 `饮品`、`饮料` 统一归入 `奶茶`）。
  映射实现收敛到 `@qsh/core` 的 `mapFoodCategory`（唯一真源），
  OFF 在线兜底（`off.client.ts`）、合并脚本、入库校验均引用它，杜绝「多处各写一份导致漂移」。
  一次性分类修复脚本：`fix-data-quality.ts`（`npx tsx ... [--write]`）。
  - **专名精确覆盖**：对「无品类词、或会被更高优先规则误抢」的专名（如「出前一丁」、
    「銀耳露」、「香草烤雞腿時蔬餐」），由 `@qsh/core` 的 `FOOD_CATEGORY_BY_NAME`
    定点纠偏（优先级最高，先于「已是合法类」短路）。**再发现同类，往该表加一行即可**
    （不必改 `seed.json`，也不会被 merge 覆盖）。
- **拼音**：`namePinyin` 用于拼音搜索，覆盖率目标 ≥ 95%。生成逻辑的**唯一真源是 `pinyin.ts`**
  （依赖 `pinyin-pro`）；`merge-seeds.ts` 在**写出种子前自动调用 `fillPinyin()`** 补全，
  所以重跑合并不会丢拼音（曾因「先跑 fill-pinyin、后并入 CFCD」导致 cfcd 拼音 0/1245、拼音搜索失效，P2-1）。
  日文/纯英文名**留空**（宁缺勿错）；若主体为英文但括号内有中文译名（如 `Yak Milk Coffee (氂牛奶咖啡)`），
  取括号内中文生成拼音。
  - **流水线顺序**：`import-cfcd.ts` → `merge-seeds.ts`（**含拼音补全**）→ `db:seed` → 重建 `food_embeddings.json`。
  - `fill-pinyin.ts` 为**独立修复 CLI**（`npx tsx infra/db/seed/fill-pinyin.ts [--write]`），仅在
    「手工改过 seed.json、想单独补拼音」时用；正常流程**无需**单独跑（merge 已内聚）。
- **入库校验**（fail-fast）：`merge-seeds.ts` 与 `apps/api/prisma/seed.ts` 均校验
  `name` 非空 / `category` ∈ 9 类 / `0 ≤ kcalPer100g ≤ 900` / 每个 `servingUnits[].grams > 0`，
  失败即报错并指出「第几条 / 哪个字段」。
- **向量重建**：改动 `name` / `namePinyin` / `aliases` / `category` 后必须重建
  `food_embeddings.json`（`node apps/api/scripts/build-embeddings.mjs`）。
- **本地测试残留清理**：`npx tsx apps/api/scripts/cleanup-e2e-food-rows.ts --write`
  （只删 `source='builtin'` 且不在本地样例集内的行）。

> **未经中国营养学会/中国疾病预防控制中心营养与健康所书面允许不得用于商业目的。**

### 本项目使用定位（红线）
- 本项目对该数据集的定位为 **个人、非商业、自用（本机学习/开发）**。
- **禁止**：上传到任何联网服务 / 云端同步、**再分发**（含随代码仓库公开）、商业用途。
- **抓取礼仪**：**串行、每次请求间隔 ≥2s**、失败退避重试、支持断点续抓（避免重复打扰平台）。

### 相关文件
| 文件 | 作用 |
| --- | --- |
| `fetch-cfcd.mjs` | 抓取分类树 + 按二级分类串行分页 → `food_items.cfcd.raw.json`（raw 36 字段原样保留，便于审计） |
| `import-cfcd.ts` | 转换：`kJ/4.184→kcal`、脏值（`—`→null / `Tr`→0）、字段映射、分类映射、名称清洗 → `food_items.cfcd.json` |
| `serving-templates.ts` | 份量模板：覆盖 **81** 个有把握的二级分类；其余（多为「其它」/婴幼儿食品）**兜底 100 克**。平台无份量数据，故不捏造具体份量 |
| `merge-seeds.ts` | 四源合并（本地/OFF/USDA/CFCD）；CFCD 与既有种子按 `normalizeName` 去重（**保留**形态/口味/部位等有区分意义的括号限定词、**丢弃**标记/数值/品牌产地），并**自动补拼音**写出 |

### 转换口径（`import-cfcd.ts`）
- 能量：平台为 **kJ** → `kcalPer100g = round(kJ / 4.184)`。
- 脏值：`"—"`（未检测）→ `null`；`"Tr"`（未检出/微量）→ `0`；空串/非数值 → `null`。**不把 null 当 0**。
- 映射字段：热量 / 蛋白 / 脂肪 / 碳水 / 总膳食纤维 / 钠 / 钙 / 铁 / 钾 / 镁 / **饱和脂肪（推算）**。
- **饱和脂肪（推算值，非平台直接给的克数）**：平台 `raw[32]` 给的是**饱和脂肪酸占总脂肪酸的百分比**，
  换算 `SFA_g/100g = 脂肪_g/100g × SFA% ÷ 100`（保留 1 位小数）。**仅当脂肪与 SFA% 均有数值**时才换算；
  任一缺失（`—`/空/非数值）→ 保持 `null`（**不推断、不用 MUFA/PUFA 反推**）。物理校验 `SFA ≤ 脂肪`，
  违反则视为解析错位/异常 → **告警并置 null**（宁可留空，不写不合理值）。
  ⚠️ **绝不把 SFA% 的百分比原值直接写进克数字段**（那会造成数倍高估）。
- **明确留空**（平台口径不匹配/无数据，不硬凑）：`sugar` / 维生素 D / B12（平台无此三项）。
- 分类：调用 `@qsh/core` 的 `resolveCfcdCategory`（映射表 `CFCD_CATEGORY_BY_PATH` 在 core，单一真源）。
- 份量：`serving-templates.ts` 的 `servingFor(一级, 二级)`。
